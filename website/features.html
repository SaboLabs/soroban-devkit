Capabilities

What sdkt does, command by command.

Every capability below is verified against the current CLI. Two badges tell you what ships where:

  • v2.7.0 in the published release and on crates.io.
  • main merged after the tag — build from source.
main

Advanced Fuzzing

Generate diverse test cases with intelligent input mutation and edge-case discovery, driven by declared expectations. Deterministic per seed, minimized on failure.

$ sdkt fuzz campaign us_new.wasm --seed 42 --cases 4
executed=4 passed=2 findings=2 skipped=0
v2.7.0

Artifact Inspection

Offline inspection of compiled WASM: size, SHA-256 hash, custom sections, build provenance, exports, and contract spec. No source needed.

$ sdkt wasm inspect us_old.wasm
Size: 198 bytes · Functions: 2 · Events: 1
v2.7.0

Upgrade Safety

Offline WASM-to-WASM diff with a breaking-change verdict, plus operator-supplied size and growth policies. No Stellar network limit is hardcoded.

$ sdkt diff --upgrade-safety --old-wasm us_old.wasm --new-wasm us_new.wasm
Compatible: NO
v2.7.0

Release Assurance

Artifact, security audit, upgrade safety, deployed verification, and contract health aggregated into one read-only verdict. A skipped section is never flattened into PASS.

$ sdkt release-assurance --wasm us_old.wasm
RELEASE STATUS REVIEW
v2.7.0

Static Security Audit

Seven built-in rules over Soroban Rust source: AUTH-001…004, MOVE-001, MATH-001, CEI-001. Extensible via sandboxed WASM or native plugins.

$ sdkt audit examples/sample_token/src/lib.rs
[critical] AUTH-001 SampleToken::admin_action
v2.7.0

CI/CD Integration

The same release-assurance engine ships as a reusable GitHub Action. It fails the step on FAIL or any non-zero CLI exit.

- uses: SaboLabs/soroban-devkit@main
with: command: release-assurance

Reports decoded build provenance (rssdkver, rsver). When absent, it reports (none) so you can audit toolchain provenance.

Release assurance

One read-only release decision.

Five sections, aggregated deterministically. A skipped section is reported as SKIPPED — never flattened into PASS.

sdkt release-assurance --wasm us_old.wasm REVIEW
Section Verdict Detail
ArtifactPASS198 B · spec present
SecuritySKIPPEDno source path supplied
Upgrade SafetySKIPPEDno --previous-wasm
VerificationSKIPPEDno --contract
Contract HealthSKIPPEDno --contract

REVIEW, not PASS: four on-chain sections are SKIPPED because --contract was omitted. Pass --contract (read-only) to run deployed verification and health.

Build · deploy · invoke

From source to chain, one flow.

Stages 01–02 run offline. Only deploy and invocation need an RPC endpoint.

  1. build sdkt build

    Compile Rust contracts into WASM artifacts

  2. deploy sdkt deploy --wasm <file> --deny-breaking

    Upload + instantiate; the guard blocks breaking upgrades

  3. invoke sdkt invoke <id> <fn> -a u32:1 -I alice

    sequence → simulate → sign → submit → poll

  4. call sdkt call <id> <fn> -a u32:1

    Read-only simulation, no signing, no submission

Install the binary, inspect a fixture, run an audit — all offline, all under five minutes.
