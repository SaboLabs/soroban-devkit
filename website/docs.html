Install

Three paths. Pick one. All produce a sdkt binary that reports a version.

A · install script (no Rust toolchain)recommended
# downloads the release binary for your OS/arch,
# verifies its SHA-256 checksum, installs to ~/.local/bin
curl -fsSL https://raw.githubusercontent.com/SaboLabs/soroban-devkit/main/install.sh | bash

# pin a version
SDKT_VERSION=v2.7.0 curl -fsSL \
  https://raw.githubusercontent.com/SaboLabs/soroban-devkit/main/install.sh | bash
B · crates.io (Rust 1.88.0+)v2.7.0
cargo install sdkt-cli
sdkt --version
# -> sdkt 2.7.0
C · build from sourcemain
git clone https://github.com/SaboLabs/soroban-devkit
cd soroban-devkit
cargo build --release
./target/release/sdkt --version

Fuzzing (sdkt fuzz) and client generation (sdkt generate) are on main and are not in the v2.7.0 release binary or on crates.io. Use path C to run them.

Quick start

Four offline steps, no RPC and no account. Every command was run against the current CLI before being written here.

1 · inspect a contract WASMoffline
# the repo ships two tiny fixture contracts
sdkt wasm inspect crates/sdkt-cli/tests/fixtures/us_old.wasm

# reports size, SHA-256, custom sections, exports, and the contract spec
2 · audit contract sourceoffline
sdkt audit examples/sample_token/src/lib.rs

# -> [critical] AUTH-001 [SampleToken::admin_action]:
#    Function `SampleToken::admin_action` looks privileged but does not call require_auth()
3 · diff an upgrade for breaking changesoffline
sdkt diff \
  --old-wasm crates/sdkt-cli/tests/fixtures/us_old.wasm \
  --new-wasm crates/sdkt-cli/tests/fixtures/us_new.wasm \
  --upgrade-safety

# -> Compatible: NO
#    Breaking: removed mint(), transfer(), event Transfer, type Point
4 · first fuzz campaignmain
sdkt fuzz campaign crates/sdkt-cli/tests/fixtures/us_new.wasm \
  --seed 42 --cases 4 --expect-error hello:Auth:6 \
  --artifact-dir ./artifacts

# -> executed=4 passed=2 expected_errors=0 findings=2 skipped=0
#    FINDING case0000 hello RETURN_MISMATCH (minimized_complexity=10)
#    evidence: completed=true findings=2 minimized=2 deterministic=true

First contract

The repository ships examples/sample_token/src/lib.rs — a minimal Soroban contract with one deliberately unguarded entrypoint so sdkt audit produces a deterministic AUTH-001 finding. It is analyzed as Rust source only; it does not need to be compiled.

Also included: examples/sample_scval.b64, a single valid base64 ScVal for sdkt decode --type ScVal without needing a network.

Fuzzing

Deterministic campaigns in an isolated in-memory Soroban host (soroban-env-host 28.0.2). Your compiled WASM never leaves your machine — no RPC, no ledger, no signing, no telemetry.

Declare expectations with --expect-success / --expect-error; violations become findings. Every finding is minimized and written as a canonical artifact that re-executes byte-identically in a separate process.

replay a recorded findingoffline
sdkt fuzz replay ./artifacts/finding-case0000-return_mismatch.json \
  --wasm crates/sdkt-cli/tests/fixtures/us_new.wasm

# -> REPRODUCED reason=RETURN_MISMATCH artifact_hash=6f54856da0f2bd…

A finding is evidence of a declaration mismatch, not a vulnerability claim. Pilot totals (45/45, 12/12, 11/11 REPRODUCED) come from three specific external contracts, not a universal guarantee. Method: fuzz-real-contract-evidence.md.

Upgrade safety

Offline WASM-to-WASM diff with a breaking-change verdict, plus operator-supplied size and growth policies (--max-size-bytes, --max-growth-pct). No Stellar network limit is hardcoded, and passing a threshold does not assert network-limit compliance.

Release assurance

Artifact, security audit, upgrade safety, deployed verification, and contract health aggregated into one read-only PASS / REVIEW / FAIL verdict. A skipped section is never flattened into PASS.

aggregated release decisionread-only
sdkt release-assurance --wasm crates/sdkt-cli/tests/fixtures/us_old.wasm

# -> Artifact PASS · Security SKIPPED · Upgrade Safety SKIPPED
#    Verification SKIPPED · Contract Health SKIPPED
#    RELEASE STATUS  REVIEW

REVIEW here, not PASS: four on-chain sections are SKIPPED because --contract was omitted. Pass --contract (read-only) to run deployed verification and health.

CI/CD

The same release-assurance engine ships as a reusable GitHub Action. It accepts wasm, optional audit, contract, and the size-policy inputs, and fails the step on FAIL or any non-zero CLI exit.

.github/workflows/release.ymlyaml
- uses: SaboLabs/soroban-devkit@main
  with:
    command: release-assurance
    wasm: target/wasm32v1-none/release/my_contract.wasm
    audit: crates/my-contract/src/lib.rs
    max-size-bytes: "131072"

Full guide: docs/compatibility/ci-cd.md.

Exit codes

Most commands exit 0 on success and 1 on a genuine input or transport error. Two gates are deliberate:

  • release-assurance — exit 1 only when release_status is FAIL; REVIEW exits 0.
  • health — exit non-zero on a critical verdict; at_risk stays 0.

sdkt audit exits 0 on findings by default. Use --fail-on <severity> to exit 1 when findings at or above that threshold exist. CI gates can also use summary.critical from --format json, or the Action's severity-threshold input.
